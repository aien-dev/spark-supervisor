# spark-supervisor: aien-supervise

AIEN's process supervisor, written in seeded Omega. It runs AIEN services without systemd units:
no `.service`, `.timer` or `.path` files, no `systemctl`, no unit sandboxing.

This repository used to hold a Rust supervisor (`spark-supervisor`, archived 2026-09). That code is
replaced here by the `.om` port; its history stays in git. The Rust crate copy in
`aien-sovereign-core` is separate and unchanged by this repository.

**Status (2026-10-26):** IMPLEMENTED and EXERCISED on the Spark (host evidence below). Allen's
services are not cut over yet: see [docs/MIGRATION.md](docs/MIGRATION.md).

## What is honest about "no systemd"

The Spark runs DGX OS (Ubuntu). PID 1 is the distribution's systemd and stays so; so do the
distribution's own units (networking, sshd, cron, journald). What aien-supervise removes is AIEN's
dependence on systemd: AIEN services are declared, started, sandboxed, restarted and logged by AIEN
code. Boot start is a cron `@reboot` line; cron itself is started by the distribution's init.

## Parts

| Program | Source | Runs as | Role |
| --- | --- | --- | --- |
| `aien-supervise` | `om/supervise.om` | the operator account | daemon (`run`), `ensure`, `status`, `start`/`stop`/`restart`, `check`, `shutdown` |
| `aien-supervise-root` | `om/root.om` | root, via one sudoers rule | builds one service's sandbox and execs it; `stop`/`kill` its cgroup; `check` (dry run) |
| `aien-watch` | `om/watch.om` | the service user, inside the sandbox | path trigger (replaces `.path` units) |

`om/lib.om` is shared; `om/syscalls.om` is generated by `tools/gen-syscalls.sh` from
`systemd-analyze syscall-filter` (group membership oracle) and `<asm/unistd.h>` (ARM64 numbers);
`tools/gen-syscalls.sh --check` fails on any difference.

## Service files

Two directories, one line per directive (`key value...`), `#` comments, no quoting:

* `~/.config/aien-supervise/services/NAME.svc`: user services, run as the operator account.
* `/etc/aien-supervise/services/NAME.svc`: sandboxed services, root-owned, not group/other-writable.

`NAME` is 1..32 bytes of `a-z 0-9 -`. Common keys:

| Key | Meaning (systemd equivalent) |
| --- | --- |
| `exec PATH ARG...` | program and arguments; PATH canonical, absolute (ExecStart) |
| `type simple\|oneshot` | default simple (Type) |
| `restart always\|on-failure\|no` | default on-failure; oneshot no (Restart) |
| `backoff MIN MAX` | restart delay MIN·2^k seconds up to MAX, reset after 60 s of uptime (RestartSec) |
| `every S` / `delay S` | oneshot period and first-run delay; last success kept, so a missed run happens at start (OnCalendar, OnBootSec, Persistent) |
| `timeout S` | oneshot run limit: SIGTERM, then SIGKILL after `stoptime` (TimeoutStartSec) |
| `stoptime S` | TERM-to-KILL grace, default 10 (TimeoutStopSec) |
| `autostart yes\|no` | start with the daemon, default yes |
| `log-max BYTES` / `log-keep N` | rotation of `state/log/NAME.log`, default 10 MiB, 3; a file can pass log-max by one read (64 KiB) |
| `env K=V` | environment; nothing else is inherited (Environment) |
| `dir PATH`, `umask OCTAL`, `nice N` | WorkingDirectory, UMask, Nice |
| `watch DIR SUFFIX PERIOD TIMEOUT` | run `exec` when DIR holds a non-hidden entry ending in SUFFIX (`*` = any); reruns on a changed set, after failure (backoff), hourly otherwise (DirectoryNotEmpty, PathExistsGlob) |

Sandboxed services only (`/etc/aien-supervise/services`):

| Key | Mechanism |
| --- | --- |
| `user NAME` (required), `group`, `groups` | uid 1..999; gid >= 100; root-equivalent groups (docker, sudo, adm, disk, lxd, kvm, shadow, libvirt, systemd-journal) refused; initgroups is computed and checked by the helper |
| `ro P` / `rw P` / `hide P` | bwrap binds; `rw` only under `/var/`, `/srv/`, `/run/`; `/home`, `/root`, `/proc`, `/sys`, `/dev`, `/tmp` refused |
| `envfile P`, `secret NAME P` | root-owned files; secrets (mode 0600/0400) are bound read-only at `/run/credentials/NAME` with `CREDENTIALS_DIRECTORY` set (ImportCredential shape) |
| `net host\|none\|filter`, `allow ADDR [PORT]`, `deny ADDR`, `net-default accept\|drop`, `listen PORT ADDR...` | `none`: empty network namespace; `filter`: nftables table `aiens_NAME` keyed by `meta skuid` (established/related accepted, allow before deny), and an input rule that admits PORT only from the listed sources (IPAddressAllow/Deny) |
| `memory-max`, `memory-swap-max`, `tasks-max`, `cpu-quota PCT` | cgroup v2 leaf `/sys/fs/cgroup/aien-supervise/NAME`: memory.max, memory.swap.max, pids.max, cpu.max (MemoryMax, MemorySwapMax, TasksMax, CPUQuota) |
| `nofile N` | RLIMIT_NOFILE (LimitNOFILE); RLIMIT_RTPRIO is always 0 |
| `namespaces yes\|no` | no: `--disable-userns` and the filter refuses unshare, setns, clone with namespace flags, clone3 (ENOSYS) (RestrictNamespaces) |
| `syscalls GROUP...` (required), `syscalls-deny GROUP...`, `syscall-error eperm\|kill` | seccomp allowlist built in Omega: `@system-service`, `@mount`, `@ns` (= unshare setns); minus `@privileged`, `@resources`; default action kill (SystemCallFilter, SystemCallErrorNumber, SystemCallArchitectures=native) |
| `families unix inet inet6 netlink` | socket/socketpair family allowlist, EAFNOSUPPORT otherwise (RestrictAddressFamilies) |
| `mdwe yes\|no` | default yes: no W+X mmap, no PROT_EXEC mprotect/pkey_mprotect, no SHM_EXEC (MemoryDenyWriteExecute) |

Always on for sandboxed services: user, pid, ipc, uts and cgroup namespaces; read-only `/usr`,
`/etc` and sandbox root; own `/proc` with `/proc/sys` and the other kernel knobs read-only; minimal
`/dev`; private `/tmp` and `/var/tmp`; no `/home`, `/root`, `/sys`; no_new_privs; empty bounding,
inheritable and ambient capability sets; personality locked; no setuid/setgid mode bits;
no realtime scheduling. The full per-directive table for Allen's units, with probes and negative
controls, is in [docs/MIGRATION.md](docs/MIGRATION.md).

## Privilege model

The daemon runs as the operator account and holds no privilege. For a sandboxed service it runs
`sudo -n /usr/local/libexec/aien-supervise/aien-supervise-root run NAME`. The helper:

1. refuses unless real and effective uid are 0 and the arguments are `run|stop|kill|check NAME`;
2. checks, like `aien-run-exec`, that every path it relies on is root-owned and not
   group/other-writable, directories included, with no symlinks: itself, `aien-watch`, `bwrap`,
   `setpriv`, `prlimit`, `nice`, `nft`, `/etc/passwd`, `/etc/group`, the service file and
   `/etc/aien-supervise/services`, the `exec` program, every `envfile` and `secret`;
3. never runs anything as root except `nft -f` (the service's own table) and `prlimit --pid` (on
   itself); the service starts as its own uid after `setpriv`, and `bwrap` runs unprivileged.

An operator account can therefore start or stop the declared services, but cannot choose what they
run, as whom, or with which rights: that needs root to edit `/etc/aien-supervise/services`.

### Sudoers (`/etc/sudoers.d/aien-supervise`, mode 0440, `visudo -cf` first)

```
Defaults!/usr/local/libexec/aien-supervise/aien-supervise-root !use_pty
<operator> ALL=(root) NOPASSWD: /usr/local/libexec/aien-supervise/aien-supervise-root run *, /usr/local/libexec/aien-supervise/aien-supervise-root stop *, /usr/local/libexec/aien-supervise/aien-supervise-root kill *, /usr/local/libexec/aien-supervise/aien-supervise-root check *
```

`!use_pty` keeps the service's output on the daemon's pipe instead of a sudo pty. The helper
validates NAME itself, so `*` cannot reach anything but `/etc/aien-supervise/services/NAME.svc`.

## Install

```sh
sudo install -d -o root -g root -m 0755 /usr/local/libexec/aien-supervise /etc/aien-supervise /etc/aien-supervise/services
sudo install -o root -g root -m 0755 out/aien-supervise-root out/aien-watch /usr/local/libexec/aien-supervise/
sudo install -o root -g root -m 0755 out/aien-supervise /usr/local/bin/aien-supervise
# crontab -e (operator account):
@reboot /usr/local/bin/aien-supervise ensure
* * * * * /usr/local/bin/aien-supervise ensure
```

State lives in `~/.local/state/aien-supervise/` (`daemon.log`, `log/NAME.log*`, `st/NAME`,
`ctl/`). `aien-supervise status` prints one line per service.

## Tests

* `sh tests/user.sh`: daemon behaviour without root (restart/backoff, timers, timeout, requests,
  escalation, environment, rotation, refusals, shutdown).
* `sudo -n sh tests/sandbox.sh`: qualifies the installed helper: probe `tests/probe.py` confined
  on 50 checks, the same probe unsandboxed reads `open` on every discriminating check, one-directive
  mutations reopen their check, 18 refusals, cgroup stop/kill lifecycle.
* `sudo -n sh tests/twin.sh SERVICE PROBE.py`: runs any probe inside an installed service's exact
  sandbox (how Allen's own isolation tests were rerun).
* `sh tools/gen-syscalls.sh --check`.

Evidence of 2026-10-26 on the Spark (aarch64, kernel 7.0.0-1019-nvidia, bubblewrap 0.9.0,
util-linux 2.39.3, nftables 1.0.9, systemd 255 as the syscall-group oracle): `SANDBOX PASS
cases=37`, `USER PASS`, `SYSCALLS-TABLE PASS`; allen-chat's gateway probe and its compile-sandbox
escape tests (17/17) inside the allen-chat sandbox; a real `allen-catalog` run inside its sandbox.

## Host helpers (recorded dependencies)

Omega (omega-mv `0d6af54f`) has no host words for these yet. Each is an unfinished migration, with
its Omega successor reserved in omega-mv's host batch (keyword IDs 198..219, owner of the queue:
OmegaNext).

| Helper | Version | Used for | Omega successor |
| --- | --- | --- | --- |
| `/usr/bin/setpriv` | util-linux 2.39.3 | uid/gid/groups, no_new_privs, capability drop | `setids`, `nonewpriv`, `capdrop` host words |
| `/usr/bin/prlimit` | util-linux 2.39.3 | RLIMIT_NOFILE, RLIMIT_RTPRIO on the helper | `rlimit` host word |
| `/usr/bin/env` | coreutils | passing an environment across exec (Omega's exec passes none) | `execenv` host word |
| `/usr/bin/nice` | coreutils | `nice` key | `setprio` host word |
| `/usr/bin/bwrap` | bubblewrap 0.9.0 | namespaces, binds, seccomp load | `unshare`, `mount`, `pivotroot`, `seccomp` host words (security review required) |
| `/usr/sbin/nft` | nftables 1.0.9 | per-uid network table | nfnetlink in Omega (with OmegaNet) |
| `/usr/bin/sudo` | sudo 1.9.15 | the single privilege crossing | none planned: the narrow rule is the design |
